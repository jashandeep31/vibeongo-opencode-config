# Pull Request Checkout Procedure

After discovering available commands:

1. Retrieve Pull Request information.
2. Check out the Pull Request branch into the current repository workspace.
3. Verify that the checked-out code matches the Pull Request being reviewed.
4. Review the actual checked-out code.

Never perform a review using only:

* The Pull Request title
* The Pull Request description
* The GitHub diff

The checked-out code is the source of truth.

The repository state is the source of truth.

The review must be based on the actual code that would be merged.

# Validation Expectations

The repository already contains the information necessary to determine how the project should be validated.

Inspect:

* Existing CI workflows
* Repository documentation
* Build configuration
* Test configuration
* Project scripts
* Existing validation processes

Use the same validation approach already used by the repository.

Do not make assumptions based on programming language.

Do not assume:

* npm
* pnpm
* yarn
* cargo
* go test
* pytest
* mvn
* gradle

Instead, discover how the repository validates changes and use that process.

The goal is to review the Pull Request using the same standards the repository itself uses.
